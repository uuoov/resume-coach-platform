# GitHub Star Growth Playbook

This document collects practical ways to make the project easier to discover, evaluate, and share. It avoids fake-star tactics and focuses on usefulness.

## 1. Make The First 30 Seconds Clear

- Keep a strong one-sentence positioning line near the top of the README.
- Show real screenshots above setup instructions.
- Explain the core loop: upload resume -> analyze JD -> score fit -> rewrite resume -> export PDF.
- Keep a no-database, no-AI-key demo path visible.

## 2. Make The First 5 Minutes Successful

- Provide a test account for local demo mode.
- Keep `docs/DEMO.md` up to date with real screenshots.
- Add a one-command demo fixture or seed script.
- Add E2E coverage so demo regressions are caught quickly.

## 3. Make The Project Searchable

- Use GitHub topics such as `resume`, `career`, `job-search`, `ai`, `typescript`, `react`, `express`, `pdf`, `ats`, `prisma`.
- Mention both Chinese and English keywords in docs.
- Add role-specific examples: frontend engineer, product manager, AI engineer, data analyst.

## 4. Make Contributions Obvious

- Keep `ROADMAP.md` current.
- Maintain `good first issue` candidates.
- Use issue templates and a PR template.
- Add small docs tasks for first-time contributors.

## 5. Make Sharing Easier

- Publish release notes with screenshots.
- Record a short GIF or video of the flow.
- Write a concise launch post explaining who the project helps and why it is different from a resume template builder.
- Share concrete examples: before/after rewrite, scoring breakdown, PDF export.

## Suggested Next Growth Tasks

- Add a hosted demo or Docker demo profile.
- Add a 60-second demo GIF to the README.
- Add sample data for three more roles.
- Add Playwright screenshots to CI artifacts.
- Add a matching-score explanation page for non-technical users.
